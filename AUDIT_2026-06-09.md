## H1 — Safety filters fail OPEN when the bulletin is missing ✓
`safety_filters.evaluate()` skips all avalanche checks when `bulletin is None`. The connector returns `None` for *both* "no bulletin in force (off-season)" and "fetch failed" (network error, 404 two days running, mirror schema change). Verified: winter scialpinismo route + no bulletin → **passes all filters** and would be handed to Gemini as "safe". For a safety product this is the wrong failure mode.
**Fix:** distinguish `NO_BULLETIN` from `FETCH_ERROR` in the connector return; in the planner, block snow-activity routes (or mark "non verificabile — bollettino non disponibile") whenever a bulletin is expected but absent. `briefing.py` already 409s on None; the planner is the hole.

## H2 — Production container cannot start ✓
`planner.py` imports `safety_filters` from `<repo_root>/trip-planner` via `parents[3]`. In the Docker image only `app/` is copied, so the path resolves to `/trip-planner` (absent) → `ImportError` at startup → Cloud Run deploy fails. The Dockerfile comment acknowledges it, but as written every deploy crashes.
**Fix:** vendor `safety_filters.py` into `app/` (single source via a sync check in CI), or make the import fall back to a packaged copy.

## M1 — Planner mixes real bulletins with fabricated weather ✓ (disclosed)
`planner._mock_forecast()` is used unconditionally, even with `USE_MOCK_DATA=false`. In live mode the wind/thunderstorm/warming filters run on invented numbers that look real, and `plan_text` doesn't disclose it. Roadmap item #3 wires the real forecast, but until then live mode should refuse to plan or label the forecast as demo data in the response.
**Fixed:** `PlanResponse` now carries `forecast_notice`, set whenever the mock forecast is in play, and the planner UI renders it as a warning ("Meteo dimostrativo… non usare per decisioni reali"). The invented numbers are no longer passed off as real. Full removal happens when roadmap #3 wires the forecast service (which now returns **501**, not a 500, in live mode).

## M2 — Prev-day bulletin fallback: wrong source link, no error handling, no expiry check ✓
In `aineva.py`, when today's file 404s and yesterday's is used: (a) `source_url` still points to today's (nonexistent) file — the liability-critical "link to the official bulletin" is wrong, and the audit log would store the wrong source; (b) the second `httpx.get` has no try/except → network error becomes an unhandled 500, and no `Accept` header; (c) `validTime.endTime` is never checked, so an *expired* bulletin can be served as in force.
**Fix:** pass the actually-fetched URL to `parse_caaml`, wrap the retry, and discard bulletins with `valid_until < now`.

## M3 — `max_slope_deg = None` crashes the planner ✓
`_to_sf_route` uses `route.get("max_slope_deg", 0)`, which returns `None` (not 0) when the DB column is NULL — then `None > 30` raises `TypeError` → 500 on `/planner/plan`. All 5 seed routes happen to have values; the first curated route without one breaks the endpoint. **Fix:** `route.get("max_slope_deg") or 0` — but note 0 also silently disables the slope check (fail-open on missing data); prefer blocking routes with unknown slope from snow-activity candidates.

## M4 — Warming filter only matches literal "S" aspect ✓
Filter 4 checks `"S" in primary_aspects`: a +8 °C spring day on an SE/SW route passes (verified). Wet-snow risk applies to the full southern sector. **Fix:** check `{"S","SE","SW"} & set(primary_aspects)`.

## M5 — Route-detail page never shows a forecast
`frontend/app/routes/[slug]/page.js` guards on `route?.start_point`, which no store returns, so the effect always returns early and the UI shows "Carico le previsioni…" forever — the demo-coord fallback in the comment is unreachable. **Fix:** drop the guard (use demo coords until real geometry lands).

## M6 — One bulletin HTTP fetch per route, per plan request ✓
The planner fetches the bulletin inside the route loop with no caching: a 100-route region = 100 live GETs to avalanche.report per planner click. **Fix:** memoize per (service, zone, date) for the duration of a request (and later via `avalanche_bulletin` cache table — already in the schema).
**Fixed:** `_make_bulletin_fetcher` memoizes per `(service, zone, subzone)` for the request — routes sharing a zone now hit the mirror once. A `BulletinFetchError` is cached too, so a failing zone isn't retried per route. Cross-request persistence still belongs in the `avalanche_bulletin` table (ETL side).

## L — Smaller items
**Fixed:** `registry.get_for_country` failures now return **503** (clear Italian message) in both planner and briefing instead of a bare 500. `forecast.py` returns **501** in live mode, not `NotImplementedError`/500. `caaml` `issued_at` fallback is now `datetime.now(timezone.utc)` (cleared during the M2 work). `/alert/subscriptions` is now scoped to a required `user_id` query param — one call can no longer dump every subscriber (real auth still pending). Briefing reports `model: "deterministic-stub"` while the text is the stand-in (audit-log truth). CORS is now env-driven (`CORS_ORIGINS` csv for non-local) rather than an empty prod list. Unused `aineva.LANG` removed; planner's stale `datetime`/`timezone` imports removed during the H/M rewrite.
**Deferred (not code bugs):** Landing waitlist shows success even when the POST fails — intentional demo behaviour, revisit when `ENDPOINT` is real. Gran Paradiso `diff_scale: FERRATA` for an alpine "F+" grade — a curator/taxonomy call; note that the enum's FERRATA values (F/PD/D/TD/ED) are actually the French alpine scale and the enum is worth renaming/ splitting.
